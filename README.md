# پنل SIEM

پنل راست‌به‌چپ React برای مرکز عملیات امنیت. نمای کلی، نمودارها، دریافت گروهی، جست‌وجو و فیلتر لاگ، قواعد تشخیص، هشدارها، پرونده‌ها، تحلیل هوشمند و وضعیت سامانه در منوی پنل قرار دارند. تم روشن و تیره با انتخاب کاربر در مرورگر ذخیره می‌شود.

## اجرای محلی

پیش‌نیاز Node.js 22.12 یا جدیدتر است.

```sh
npm ci
npm run dev
```

پنل روی `http://localhost:5173` اجرا می‌شود. برای تست و ساخت نسخهٔ استاتیک از فرمان‌های زیر استفاده کنید.

```sh
npm test
npm run build
```

خروجی build در `dist/` قرار دارد. در بخش‌های ماک، داده‌ها با بارگیری صفحه بازنشانی می‌شوند. ثبت گروه، وضعیت پرونده یا هشدار و فعال‌سازی قاعده فقط بر داده‌های همان نشست اثر می‌گذارند.

## قرارداد بک‌اند

منو از پاسخ واقعی و فیلترشدهٔ `GET /api/v1/system/navigation` ساخته می‌شود. پنل از همان نام مسیر، پارامتر، فیلدهای JSON و وضعیت‌ها استفاده می‌کند.

| نما | مسیرهای مورد استفاده (پیشوند `/api/v1`) |
| --- | --- |
| نمای کلی | `GET /overview`، `GET /dashboard/charts`، `GET /search/events` |
| دریافت و پردازش | `POST /ingestion/batches`، `GET /ingestion/batches/{batch_id}`، `GET /logs` |
| رویدادها | `GET /search/events` |
| قواعد، هشدارها و رخدادها | `GET /detections/rules`، `GET /alerts`، `GET /incidents` و `PATCH` مسیرهای شناسه‌دار |
| تحلیل هوشمند | `GET /datasets/folders`، `GET /normalization/records`، `GET /standardization/records`، `GET /system/status` |
| مدل جاری | `GET /ml/model`، `POST /ml/predict`، `POST /ml/predict-matrix` |
| سامانه | `GET /system/settings`، `GET /system/status`، `GET /health` |

نمای کلی از `GET /api/v1/overview` و در صورت دسترسی به رویدادها از `GET /api/v1/search/events` استفاده می‌کند. نمودارها و رویدادهای نمونه هنگام نبود داده با عنوان «دادهٔ نمونه» نمایش داده می‌شوند.

همهٔ درخواست‌ها از `src/api.js` عبور می‌کنند. انتقال پیش‌فرض `mockRequest` است. ورود، خروج، مدیریت کاربران، منو، «کاوش داده‌ها» و «مدل جاری» از انتقال واقعی HTTP استفاده می‌کنند. برای اتصال بعدی می‌توان نمونهٔ API را با `createApi({ request: fetch })` ساخت. در توسعه، Vite مسیر `/api/v1` را به FastAPI روی `127.0.0.1:8000` پراکسی می‌کند. در استقرار واقعی همان مسیر را در مبدأ پنل به بک‌اند هدایت کنید. قرارداد منو و عملیات در [بک‌اند SIEM](https://github.com/hosseini-milad/siem) قرار دارد.

## کاوش داده‌ها

«کاوش داده‌ها» داده‌های شبکه و لاگ‌های چند روز را با صفحه‌بندی نمایش می‌دهد. روز بر اساس منطقهٔ زمانی مرورگر تفسیر می‌شود. «همهٔ روزها» محدودهٔ تاریخ را برمی‌دارد. فیلترهای پیشرفته با هم اعمال می‌شوند. جزئیات هر رکورد شامل نسخهٔ خام و در صورت وجود نسخهٔ نرمال‌شده و امتیاز مخاطرهٔ ثبت‌شده در `standard_records.Label` و سند استاندارد متناظر است.

این صفحه از مسیر واقعی `GET /api/v1/explorer/records` می‌خواند. FastAPI باید فعال باشد. در توسعه مقصد پیش‌فرض Vite برابر `http://127.0.0.1:8000` است و می‌توان آن را قبل از اجرای Vite با `SIEM_API_TARGET` تغییر داد. در انتشار استاتیک، مسیر `/api/v1` باید از همان مبدأ پنل به FastAPI هدایت شود. شروع بازهٔ روز شامل و پایان آن انحصاری است.

تب «داده‌های سیستم‌ها» رکوردهای برچسب‌خورده را از `GET /api/v1/explorer/system-records` می‌خواند. جزئیات شامل لاگ خام، ویژگی‌های استانداردشده و احتمال کلاس‌هاست.

## مدل جاری

تب «مدل لاگ سیستم‌ها» مدل فعال، وزن ترکیب و ویژگی‌ها و ارزیابی هر کلاس را از `GET /api/v1/system-log-ml/models/current` نمایش می‌دهد.

از «تحلیل هوشمند ← مدل جاری» به ترتیب ستون‌های ورودی، اهمیت ویژگی‌ها در هر مدل، وزن‌های ترکیب و نمودار پیش‌بینی دسترسی دارید. صفحه نیازمندی‌های رکورد استاندارد، ماتریس و در صورت پشتیبانی مدل، رکورد خام را نمایش می‌دهد. می‌توانید اطلاعات را تازه‌سازی کنید، JSON آن را دریافت کنید یا با ورودی نمونه پیش‌بینی را بدون ذخیره در پایگاه داده آزمایش کنید.


## ورود و کاربران

ابتدا FastAPI و MongoDB را اجرا کنید و حساب نخست مدیریت کل را از مخزن بک‌اند با `.venv/bin/python -m app.bootstrap_manager` بسازید. سپس در پنل وارد شوید. مدیریت کل از **سامانه ← کاربران** سطح مشاهده یا انجام عملیات را برای هر حساب تعیین می‌کند. ادمین دارای مجوز عملیات کاربران می‌تواند کلاینت خودش را تعریف و ویرایش کند و نام شاخهٔ خود را دستی تغییر دهد. شاخهٔ کلاینت از ادمین سازنده به ارث می‌رسد. مدیریت کل حساب‌ها را همراه با شاخه و سیستم‌ها را به تفکیک شاخه می‌بیند.

پیام‌های خامی که بک‌اند از UDP دریافت می‌کند در **کاوش داده‌ها ← لاگ‌ها** نمایش داده می‌شوند. برای دریافت پیام‌های تازه با همان بازه و فیلترها، **به‌روزرسانی لاگ‌ها** را بزنید.

سلامت سیستم‌ها از حساب‌های کلاینت خوانده می‌شود. مشخصات سیستم، از جمله نوع، IP، MAC و آستانه، در بک‌اند ذخیره می‌شوند. مصرف منابع ماک است. مصرف تا آستانه سبز، بالاتر از آن زرد و در صورت عبور از ۱۲۰٪ آستانه قرمز است. کلاینت با مجوز مشاهدهٔ سلامت فقط کارت سیستم خودش را می‌بیند.


## تسک‌ها

در **تسک‌ها** همهٔ ارجاع‌های مجاز در یک کانبان نمایش داده می‌شوند. همهٔ حساب‌های فعال می‌توانند تسک بسازند و به خودشان یا گیرندهٔ مجاز ارجاع دهند. هر کارت شناسه، ایجادکننده، زمان ایجاد، آخرین تغییردهنده، تگ‌ها، اولویت، آواتار مسئولان و شمار کامنت‌ها را نشان می‌دهد. نام مسئول با نگه‌داشتن ماوس روی آواتار نمایش داده می‌شود. از آواتار نوار بالا می‌توان تصویر حساب را بارگذاری کرد. هر ستون ابتدا پنج تسک دارد و با پیمایش همان ستون تعداد بیشتری بارگذاری می‌شود. تسک پس از ۲۴ ساعت از زمان خاتمه در تابلو پنهان می‌شود. برای افزودن تگ جدید Enter بزنید یا یکی از پیشنهادهای قبلی را انتخاب کنید. کارت قابل ویرایش را می‌توان با ماوس به ستون مجاز منتقل کرد. با باز کردن کارت می‌توانید بسته به مجوز خود کامنت بگذارید، وضعیت را تغییر دهید، ارجاع و اولویت را اصلاح کنید یا تسک را خاتمه دهید. در **مدیریت ستون تسک‌ها** ادمین دارای مجوز، نام و ترتیب ستون‌های شاخه و محدودهٔ مشاهدهٔ آن‌ها را تنظیم می‌کند. اطلاعات تسک و ستون‌ها در بک‌اند ذخیره می‌شوند.


## هشدارها و سامانه

تب‌های «هشدار شبکه» و «هشدار سیستم‌ها» آخرین هشدارها، روند روزانه، شدت و وضعیت را از API می‌خوانند. جزئیات هشدار شواهد موجود را تا رکورد منبع نشان می‌دهد. هشدارهای قدیمی بدون دسته در شبکه نمایش داده می‌شوند. تحلیلگر دارای دسترسی عملیات می‌تواند از شناسهٔ یک لاگ برچسب‌خورده هشدار سیستم ثبت کند و وضعیت آن را پیگیری کند.

دو تب زندهٔ سامانه آمادگی مدل، حجم ذخیره‌سازی، آخرین دریافت و تنظیمات عمومی هر مسیر را نشان می‌دهند. تب «قابلیت‌های نمونهٔ SIEM» چهار طرح نمایشی دارد. الگوهای مرجع عبارت‌اند از [پایش Elastic Agent](https://www.elastic.co/docs/reference/fleet/monitor-elastic-agent)، [پوشش MITRE ATT&CK](https://www.elastic.co/docs/solutions/security/detect-and-alert/mitre-attack-coverage)، [فهرست‌های مقادیر](https://www.elastic.co/docs/solutions/security/detect-and-alert/create-manage-value-lists) و [رسیدگی به هشدارها](https://www.elastic.co/docs/solutions/security/detect-and-alert/manage-detection-alerts).

### کاوش وب‌سرویس‌ها

تب «وب‌سرویس‌ها» در کاوش داده‌ها درخواست‌های منتخب را از `/api/v1/explorer/web-records` نمایش می‌دهد. فیلترها شامل روز، سرویس، شناسهٔ درخواست، پیشوند مسیر، متد، کد HTTP، IP مبدأ، حداقل زمان پاسخ و حداقل حجم پاسخ هستند. در جزئیات، هدرهای مجاز و نام فیلدهای JSON در صورت موجود بودن نمایش داده می‌شوند. مدت نگهداری رکوردها ۷ روز است.
